# リリース判定集約ツール仕様

## 目的

複数リポジトリのリリース可否を同じ基準で判定し、開発者と運用担当者が阻害要因を追跡できるコマンドラインツールを提供する。

## 利用者の操作

利用者は対象リポジトリと基準ブランチを設定ファイルへ記載し、`release-readiness check` を実行する。ツールは各リポジトリの必須ステータスチェック、未解決レビュー、未完了Milestone、未解決の重大Issueを取得し、判定結果を標準出力へ返す。

`--format json` では機械可読な結果を、`--format markdown` では人が読める一覧を出力する。全対象が条件を満たせば終了コード0、阻害要因があれば2、設定または通信の失敗は1を返す。

## 機能要件

- YAML設定を読み、所有者、リポジトリ、基準ブランチ、Milestone、重大度の閾値を検証する。
- GitHub APIの認証情報は環境変数から読み、設定やログへ値を出さない。
- 必須ステータスチェック、レビュー判断、Milestone、Issueを取得する。
- APIのページングと一時的な失敗に対応し、再試行回数を設定できる。
- 取得結果をリポジトリ単位で正規化し、阻害要因と根拠URLを保持する。
- JSONとMarkdownの両形式で、総合判定、リポジトリ別判定、阻害要因を出力する。
- `--repo` で対象を1件に絞り、`--offline` で保存済み応答から再判定できる。
- 通常実行ではアクセストークンや応答本文をログへ出さない。

## 品質要件

- Python 3.12以上で動作する。
- 設定解析、判定規則、出力整形は単体テストを持つ。
- APIクライアントは録画済み応答による統合テストを持ち、実GitHub接続をテストの必須条件にしない。
- コマンドの主要経路は一時ディレクトリを使うE2Eテストで確認する。
- 100リポジトリを対象にした保存済み応答の再判定を30秒以内で終える。
- 利用方法、設定例、終了コード、障害時の確認方法を文書化する。

## 対象外

- GitHub上の検査、レビュー、Milestone、Issueを変更する機能。
- リリースの作成、配布、ロールバック。
- GitHub以外のサービスとの連携。
- 常駐サーバーと画面。

## 初回リリースの受け入れ条件

- 3件以上のリポジトリを含む設定で、成功、阻害、通信失敗を区別して報告できる。
- JSONとMarkdownが同じ総合判定と阻害要因を示す。
- 秘密情報を含む入力を使っても、標準出力、標準エラー、保存済み応答へ秘密情報が残らない。
- オフライン再判定と主要な確認手順がCIで再現できる。
