# 2026-08-01 stacked PR運用の評価

対象は、`2ab95ed`の`github-issue-pr-ops`と、同じ問い合わせ集合を持つ`github-project-ops`である。利用者の指示により追加評価を打ち切り、完了した試行だけを記録する。

## 判定範囲

- 発火評価は、スキル本文を見ていない新しい実行担当が`description`と問い合わせだけを使って分類した。
- 学習用20問、検証用8問、未使用の境界確認3問を各3回実行した。
- 出力評価は、対象スキル、場面、採点条件だけを新しい実行担当へ渡した。
- GitHubへの変更操作は行っていない。
- 実際の自動読み込み率は未測定であり、`description`の独立分類結果と混同しない。

## 発火境界

翻訳だけを求める問い合わせの除外を`description`へ明記した後、31問を新しい3実行担当で再判定した。93件の問い合わせ判定、186件のスキル別真偽値は、すべて期待値と一致した。新しい不明点の報告は0件だった。

| 問い合わせ集合 | Issue/PRのみ | Projectのみ | 両方 | どちらも不要 | 実行回数 | 結果     |
| -------------- | ------------ | ----------- | ---- | ------------ | -------- | -------- |
| 学習用20問     | 5            | 5           | 5    | 5            | 各3回    | 全件一致 |
| 検証用8問      | 2            | 2           | 2    | 2            | 各3回    | 全件一致 |
| 未使用3問      | 0            | 0           | 0    | 3            | 各3回    | 全件一致 |

`github-project-ops`では、Projectを含まないStack依頼を`false`とした。Projectのフィールドやビューも変更する依頼だけ、両スキルを`true`とした。

## 出力品質

中断した試行は採点結果へ含めていない。

| 場面                                    | 完了した確認              | 打ち切り時点の扱い             |
| --------------------------------------- | ------------------------- | ------------------------------ |
| Projectなしの単一Issue本文              | 2回とも6 / 6              | 完了                           |
| 仕様からのIssue分割                     | 2回とも6 / 6              | 完了                           |
| 二重着手の停止、引き継ぎ、PR契約        | 2回とも6 / 6              | 完了                           |
| 1つの`worktree`で3段のStackを作成       | 修正途中の完了試行で7 / 7 | 最終修正後の新規再試行は未完了 |
| 複数`worktree`の既存PRを`gh stack link` | 最終修正後の1回で7 / 7    | 予定した2回目は未完了          |

最初の3場面では、採点条件違反と新しい指示上の不明点はなかった。入力で未指定のリポジトリ保護設定や未送信変更は、推測せず確認する前提条件として扱われた。

Stack作成場面では、修正途中の完了試行が採点条件を満たした。その後も指示の穴が見つかったため本文を直したが、最後の修正後に予定していた新しい実行担当による収束確認は、利用者の打ち切り指示に従って中止した。

既存PRの連結場面では、base差異からの復旧条件を直した後の1回が採点条件を満たし、新しい不明点もなかった。2回目は中断したため、2回連続の収束は主張しない。

## 修正台帳

- **発火境界**: 翻訳だけの依頼が除外対象か不明瞭だった。
  - **修正**: `description`へ翻訳だけの依頼を明示した。
- **branch作成**: `gh issue develop`と`gh stack add`を使う各段の開始点が不足していた。
  - **修正**: 最下段から順にlinked branchを作り、commitとpushの後に次段を追加する手順を固定した。
- **部分マージ**: 対象範囲外の上段PRが失敗した場合の帰属が不明瞭だった。
  - **修正**: 選択範囲のheadで再現する失敗、契約違反、上段だけの失敗、帰属不能を分けた。
- **構成差異**: GitHub側のbase変更を検出した後の復旧方法が不足していた。
  - **修正**: baseだけの差異、末尾追加、並べ替え・削除、途中までの`link`成功を分け、人間の確認なしに構成を変えない規則を追加した。
- **`rerere`**: リポジトリ設定を変更する同意の範囲が広すぎた。
  - **修正**: 設定名、現在値、変更値、影響を示した明示同意を必須にした。
- **専用`worktree`**: どのremoteとtrunkから作るかが不足していた。
  - **修正**: 検証済みの`REMOTE/TRUNK`を取得し、detachedな専用`worktree`を作る手順を固定した。
